## 동시에 일하기 위한 약속 (중요)

- **`web/`만 고칩니다.** 같은 시간에 승진 님이 `server/`를 고치고 있습니다
- 승진 님이 만들 새 API의 응답 모양은 팀장이 **`shared/mock/next/`**에 먼저 만들어 두었습니다. **이 예시로 먼저 만들고**(`?mode=mock&scenario=…`), 승진 님 PR이 머지되면 실제 API로 확인합니다. 필드가 이상하면 고치지 말고 팀장에게
- `shared/`는 고치지 않습니다(두 사람 PR이 다 머지되면 팀장이 `next/`를 `mock/`에 합칩니다)

### 1. 검색을 카카오(`/api/search`)로 + 장소 이름을 패널 제목에 (F2·F18)

- 왜: Nominatim은 지번 주소("용현동 88-16")를 못 찾고 동으로 떨어집니다. 백엔드가 카카오 로컬 검색을 대신 물어 주는 `GET /api/search?q=`를 만듭니다(키는 화면에 안 둠)
- 약속(예시): `shared/mock/next/search_ok.json`(장소 이름) · `search_address_ok.json`(지번) · `search_empty.json` · `search_outside_area.json`(강화 등) · `search_outside_incheon.json`(서울 등)
  - `{"query", "status", "results": [{"name", "address", "lon", "lat", "inside"}]}`, `status`: `ok` | `empty` | `outside_incheon` | `outside_area`, 실패는 HTTP 503
- 할 것
  - `web/search.mjs`: Nominatim 대신 `${base}/api/search?q=`(mock이면 위 예시). **하루 캐시(localStorage)는 뺍니다** — 카카오는 검색 결과 저장 금지
  - 결과가 하나면 바로 이동, 여럿이면 검색창 아래 짧은 목록(최대 5개, 이름 + 짧은 주소)에서 고르기. 엔터 때만 묻기(자동완성은 안 함 — 요청 수)
  - **패널 제목에 장소 이름**: 검색으로 고르면 "인하대학교 · 미추홀구"처럼(지금은 "미추홀구 부근"). 지도를 직접 누르면 지금처럼 "○○구 부근"
  - 상태별 문구: `empty` "결과가 없습니다. 장소 이름이나 주소로 검색해 주세요." / `outside_incheon` "인천 밖의 장소예요. 인천 안의 장소로 검색해 주세요." / `outside_area` "CCTV가 없는 곳(영종·강화·섬)은 추정하지 않아요. 인천 내륙과 송도를 검색해 주세요." / 503·연결 실패 "검색을 잠시 쓸 수 없어요. 지도를 직접 눌러 주세요."
  - 검색창 안내 "장소 이름이나 주소로 검색", 출처 줄 "검색: 카카오"(OpenStreetMap/Nominatim 표기는 지도 출처에 남아 있으므로 검색 줄에서만 바꿈)
- 완료 기준: mock 네 경우 + 503 문구, 지번 예시로 이동, 결과 여럿이면 목록, 캐시 없음(테스트 `search.test.mjs` 고치기)

### 2. 지도 상태 한 줄 + 아이콘 (F13)

- 왜: 지금은 측정소 지도면 "밤·결측 대체 · 측정소 실측 기반 보간" 한 가지라 비 때문인지 밤 때문인지 모릅니다
- 약속: `/api/frames/latest`에 `reason`·`cctv`가 더해집니다. 예시 `shared/mock/next/frames_latest.json` · `frames_latest_night.json` · `frames_latest_rain.json` · `frames_latest_few.json`
- 문구(제목 카드의 `#source` 자리, 앞에 작은 아이콘). 아이콘은 이모지보다 **작은 SVG 선 아이콘**(기기마다 이모지 모양이 달라서)
  - `normal` ☀ "정상 · CCTV {total}대 중 {valid}대로 추정"
  - `night` 🌙 "밤 · 어두운 사진은 추정하지 않아 측정소 실측으로 표시"
  - `rain` 🌧 "비 · CCTV 추정을 쉬고 측정소 실측으로 표시"
  - `humidity` 💧 "습도 높음(95% 이상) · CCTV 추정을 쉬고 측정소 실측으로 표시"
  - `few_cameras` "카메라 부족 · CCTV {total}대 중 {valid}대만 값이 있어 측정소 실측으로 표시"
  - `no_data` "CCTV 자료 없음 · 측정소 실측으로 표시"
  - 필드가 없으면(옛 응답) 지금 문구 그대로
- 휴대폰은 지금 `#source`가 숨겨져 있습니다 → 아이콘 + 짧은 말("비 · 측정소 실측")만이라도 보이게
- 비 애니메이션은 넣지 않습니다(일부 지역 비인데 지도 전체에 비가 오는 그림이 됨)
- 완료 기준: mock 네 상태 + 필드 없는 옛 응답

### 3. 근거를 건너뛴 이유 문구 (F14)

- 왜: 가장 가까운 CCTV가 끊겼거나 측정소가 비었으면 백엔드가 다음 곳을 주고 `nearest`에 건너뛴 곳과 이유(코드)를 줍니다. 화면은 그걸 **사실대로, 출처를 밝혀** 한 줄로 씁니다. 제공 기관 문제를 우리 고장처럼 쓰지 않는 게 원칙입니다
- 약속: `shared/mock/next/point_inside.json`(`nearest: null`) · `point_fallback.json`(둘 다 건너뜀)
- 문구(해당 칸 제목 바로 아래, 작은 글씨). `{since}`는 "13:20", 없으면 "지금"
  - 카메라 `no_feed`: "가까운 {이름} CCTV({거리}km)는 인천교통정보센터 영상을 {since}부터 받지 못해, 다음으로 가까운 {보여 준 카메라}({거리}km) 사진입니다"
  - `rain`: "…는 비가 와서 이번 회차는 추정을 쉬어, …" / `humidity`: "…는 습도가 95% 이상이라 이번 회차는 추정을 쉬어, …" / `weather_missing`: "…는 기상청 습도 자료가 오지 않아 이번 회차는 추정을 쉬어, …" / `photo_error`: "…는 이번 회차 사진을 처리하지 못해, …"
  - 측정소(`reason`이 문자열): "가까운 {이름} 측정소({거리}km)는 에어코리아에 '{reason}'로 표시되어, 다음으로 가까운 {보여 준 측정소}({거리}km) 실측입니다" / `reason: null`: "…는 에어코리아에 이 시각 값이 올라오지 않아, …"
- 완료 기준: mock 두 경우, 모르는 코드가 오면 이유 없이 "가까운 ○○ 대신 다음으로 가까운 ○○입니다"

- 함정: 카드들은 `position:fixed`라 `offsetParent`가 늘 `null` → 보이는지는 `getClientRects().length`로
- 완료 기준: 노트북에서 핀·가장자리 핀·상세 상자, 휴대폰에서 안 깨짐

### 5. 원리 페이지에 갔다 오면 보던 곳으로 (F3)

- 지금은 돌아오면 지도가 첫 화면으로 갑니다. **같은 탭은 유지**합니다(새 탭은 전시 노트북에 탭이 쌓이고 전체 화면이 풀림)
- 보던 시점(중심·줌·기울기·방향)과 고른 지점을 `sessionStorage`에 두고, 돌아오면 첫 화면 대신 그 상태로(고른 지점이 있으면 패널도 다시)
- 완료 기준: 지점 고름 → 원리 → 돌아가기 → 같은 시점·패널, 새로 열면 첫 화면
